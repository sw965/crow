# 実験の生ログ

実行日: 2026-08-14。環境: Windows 11 / Go 1.26.5 / 12論理コアCPU。
構成は 784→512→1024、ETFプロトタイプ(全モデルで共有)、
lr=0.1 / margin=0.5 / gsize=4 / gate=1.0 / noise=0.5、ミニバッチ1024、
学習データの10%を検証。MNIST、seed=1。

「単体」はそのモデル自身、「SWA」はそれまでの全モデルを集約したもの。
「1個目との重み一致率」は可視重み W の一致割合で、無関係なら 0.5 になる。

---

## 0. 集約実装の不具合と修正

初回の測定は集約の不具合で歪んでいた。手がかりは多数決の異常な規則性だった。

```text
修正前(多数決、warmup=20、1エポック間隔)
モデル2: SWA(2個) test 0.1891
モデル3: SWA(3個) test 0.9028
モデル4: SWA(4個) test 0.5115
モデル5: SWA(5個) test 0.9039
モデル6: SWA(6個) test 0.6855
モデル7: SWA(7個) test 0.9033
モデル8: SWA(8個) test 0.8456
モデル9: SWA(9個) test 0.9039
```

偶数個のときだけ崩れる = 票の同点が全て +1 へ倒れていた。
同点を H の総和の符号で解くよう修正した。

```text
修正後(同条件)
モデル2: SWA(2個) test 0.8946
モデル3: SWA(3個) test 0.9028
モデル4: SWA(4個) test 0.8898
モデル5: SWA(5個) test 0.9039
モデル6: SWA(6個) test 0.8944
モデル7: SWA(7個) test 0.9033
モデル8: SWA(8個) test 0.8975
モデル9: SWA(9個) test 0.9039
モデル10: SWA(10個) test 0.8995
```

平均側にも同種の不具合があった。`sum/count` の整数除算が0方向へ切り捨てるため、
平均の絶対値が1未満の負の重みが `sign(0)=+1` で +1 に化けていた。
符号を総和から取るよう修正し、軌跡SWA(1エポック間隔、10個)が 0.6664 → 0.7690 に改善した。

| 条件 | テスト精度 |
|---|---:|
| 教師アンサンブル(5個) | **0.9071** |
| 単体モデル(正解ラベル) | 0.9011 |
| 蒸留 vote | 0.8969 |
| 蒸留 hard | 0.8906 |

どちらの蒸留も単体モデルに届かない。

生徒は約10%ずれた目標で学習していることになる。
