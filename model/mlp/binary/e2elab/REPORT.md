# 実験報告: 固定プロトタイプからバックボーンへ送る学習信号を変える

- 日付: 2026-08-14
- 動機(依頼): 後付けの整数読み出しは「バックボーンが不完全でも最後の分類器が救う」構造で、
  END-TO-END の美しさが失われる。最後まで二値ネット自身が表現を作り学習してほしい。
  BEP は最終活性へ固定プロトタイプ `P_y` の完全再現を要求するが、
  分類に本当に必要なのは `P_y·a > P_c·a (c≠y)` だけであり、
  BEP は分類問題を、より厳しい「符号再現問題」へ変換してしまっている。
  ここを改善できないか。
- 実験環境: Windows 11 / Go 1.26.5 / 12論理コアCPU
- 実験コード: 同フォルダ `main.go`。生ログ: `LOGS.md`
- **crow / omw のライブラリコードは変更していない**

本フォルダでは、2回に分けて次の案を検証した。

- **実験A**: 出力分類器を学習可能な二値層にする(ETF初期値)+ 目標を「正解と最大競合の差」にする
- **実験B**: 分類器は固定したまま、目標を指定するビットを絞る
  (競合差分の全ビット / 競合差分から n 個 / 全ビットから n 個)

## 1. 結論

**どの案も元の BEP を上回らなかった。** 3シード、検証分離、テストは選択に不使用。

### MNIST

| 条件 | 目標を指定するビット | テスト精度 |
|---|---|---:|
| **元のBEP** | 全1024ビット(`P_y`) | **0.9041** |
| ランダム全体 n=512 | 全ビットから無作為に512個 | 0.8990 |
| 分類器のみ学習 | 全ビット(`Q_y`、Qは学習) | 0.9030 |
| 競合差分(全部) | `P_y≠P_r` の全ビット(約512) | 0.8930 |
| 提案 n=512 | 競合差分から無作為に512個 | 0.8918 |
| ランダム全体 n=128 | | 0.8904 |
| 提案 n=128 | | 0.8855 |
| 分類器学習 + 競合差分 | | 0.8950 |
| 競合差分 + ゲート除外 | | 0.8790 |

### Fashion-MNIST

| 条件 | テスト精度 |
|---|---:|
| **元のBEP** | **0.8246** |
| ランダム全体 n=512 | 0.8229 |
| 分類器のみ学習 | 0.8226 |
| 競合差分(全部) | 0.8209 |
| 提案 n=512 | 0.8196 |
| 提案 n=128 | 0.8027 |
| ランダム全体 n=128 | 0.7966 |
| 分類器学習 + 競合差分 | 0.8206 |
| 競合差分 + ゲート除外 | 0.8117 |

要点は3つある。

1. **信号を絞るほど単調に悪化する**(§4.1)。指定ビット数 n を 8 → 32 → 128 → 512 → 全部
   と増やすと精度も単調に上がり、全部(= 元のBEP)が最良。
   これは学習量の不足ではない。エポックを32倍にして総信号量を揃えても追いつかず、
   **級内/級間比が頭打ちになる**(§4.5)
2. **「競合差分から選ぶ」ことに一貫した利点がない**(§4.2)。同じ n 個でも、
   MNIST では**全ビットからの無作為選択の方が勝つ**(n=128 / 512 とも3シードすべて)。
   Fashion の n=128 では逆に競合差分が勝つ(3/3)ので、**符号がデータセットとnで入れ替わる**
3. **級内/級間比が精度と強く相関する**(§4.3。Spearman 約 −0.93。
   順序が完全に一致するわけではない)。同じクラスの入力が同じ符号へどれだけ
   集まっているかが、精度をおおむね決めている
4. **「選ばなかったビットから信号を送らない」の忠実版(`-hard`)はさらに悪い**(§4.4)。
   n=512 で −1.04pt(3シードすべて)

> **BEP が「過剰に厳しい」符号再現を要求しているのは、欠陥ではなく機能している。**
> 全ビットを `P_y` へ揃えさせることが、同じクラスの入力の表現を1点へ凝集させており、
> プロトタイプ最近傍で読む限り、その凝集こそが精度を支えている。
> 「判別に無関係なビット」の更新は点数差には効かないが、**級内凝集には効いていた**。

## 2. 何を実装したか

推論経路は最後まで**二値活性・二値可視重み・XNOR・popcount・整数比較**だけで、
整数読み出しは存在しない。

**分類器**: `Q_c = sign(H_c)`。`H_c` は BEP と同じ整数隠れ重み(int8)。初期値は ETF プロトタイプ。
ロジットは一致ビット数(= 総ビット数 − ハミング距離)。
`-learnq=false` なら `Q` は一切動かない(`TestClassifierNotLearnableStaysFixed` で検証済み)。

**競合クラス**: `r = argmax_{c≠y} (P_c · a)`。正解以外で最も出力に近いプロトタイプ。
誤分類していれば通常は誤って推論したクラス、正解していれば「次に間違えそうな2位」になる。

**目標の作り方**(`-target` と `-n`): まず「目標を指定するビット」の選択マスクを作り、
選ばれたビットには `P_y` の値を、選ばれなかったビットには**現在の活性をそのまま**置く。
現在の活性と一致するビットは BEP の逆伝播で更新対象に選ばれないため、
これが「誤差信号を送らない」の実装になる。

| モード | 選択マスク |
|---|---|
| `proto` | 全ビット(従来のBEP) |
| `diff` | `P_y ≠ P_r` のビット全部 |
| `randdiff` + `-n N` | `P_y ≠ P_r` のビットから無作為に N 個 |
| `randall` + `-n N` | 全ビットから無作為に N 個 |

`-hard` を付けると、選ばれなかったビットをゲートからも外し、
後方射影 `sign(Wᵀ(g⊙t))` にも寄与させない(§3 の `diffgate` に相当)。

**分類器の学習**(`-learnq`): 正解クラス行を現在の活性へ近づけ、最大競合クラス行を遠ざける。
バッチで集約して符号を取り、確率 `clslr` で適用する(BEPの層と同じ枠組み)。

## 3. 実験A: 分類器を学習可能にする

| 条件 | MNIST | Fashion |
|---|---:|---:|
| 元のBEP(目標 `P_y`、分類器固定) | **0.9041** | **0.8246** |
| 目標のみ `diff`(分類器固定) | 0.8930 | 0.8209 |
| 分類器のみ学習(目標 `Q_y`) | 0.9030 | 0.8226 |
| 分類器学習 + 目標 `diff` | 0.8950 | 0.8206 |
| `diff` + ゲート除外(`-hard`) | 0.8790 | 0.8117 |

- **分類器を学習可能にすること自体は、ほぼ無害**(MNIST −0.11pt、Fashion −0.20pt)。
  分類器行が崩壊することもない(最小ペア距離 565 → 522〜539、平均 569 → 559)
- 精度を落としているのは**目標の作り方の変更**(MNIST −1.11pt)
- **ゲート除外は逆効果**。「指定なしビットが後方射影を汚染している」という仮説は
  これで否定された。後方射影はゲート内ビットの多数決なので、
  寄与するビットを半分に減らすと投票がノイジーになる。汚染よりも票数の減少の方が痛い

なお元論文は、分類器を学習させる方向を検討した上で「固定する方が実用的かつ効果的だった」と
報告している(3.1節)。実験Aの結果はその経験的結論と整合する。
ただし本実験が測ったのは「ETF初期値 + 競合クラスを意識した更新」という具体案1つであり、
学習可能な分類器一般が否定されたわけではない。

## 4. 実験B: 目標を指定するビットを絞る

分類器は固定したまま、目標を指定するビットの数と選び方を変える。

### 4.1 指定ビット数 n の掃引(MNIST、seed=1、20エポック)

| n | 提案(競合差分から) | 対照(全ビットから) |
|---|---:|---:|
| 8 | 0.5023 | 0.7551 |
| 32 | 0.8665 | 0.8675 |
| 128 | 0.8850 | 0.8908 |
| 512 | 0.8911 | 0.9004 |
| 全部 | 0.8930(= `diff`) | **0.9055**(= 元のBEP) |

**単調である。** n を増やすほど良くなり、絞ることは常に損になる。
n=8 まで絞ると MNIST で 50% まで落ちる。

### 4.2 提案 vs 対照(3シード)

| データセット | n | 提案(競合差分から) | 対照(全ビットから) | 差 |
|---|---|---:|---:|---:|
| MNIST | 128 | 0.8855 | **0.8904** | 対照が +0.49pt(3/3) |
| MNIST | 512 | 0.8918 | **0.8990** | 対照が +0.72pt(3/3) |
| Fashion | 128 | **0.8027** | 0.7966 | 提案が +0.61pt(3/3) |
| Fashion | 512 | 0.8196 | **0.8229** | 対照が +0.33pt(2/3) |

**符号がデータセットと n で入れ替わる。** したがって「判別に必要なビットを選ぶ」という
発想そのものには、一貫した効果が無いと判断する。

特に象徴的なのは MNIST で、**「全ビットから無作為に512個」(0.8990)が
「判別に効く512ビットを狙って選ぶ」(0.8930 = `diff`)を上回った**ことである。
狙って選ぶより無作為の方が良い。

この対照条件は GPT の提案によるもので、**「改善が単なる更新量の削減によるものか、
競合との差分を選んだことによるものか」を切り分ける**目的だった。
結果は「どちらでもない。どちらも元のBEPより悪い」であり、対照を置いた価値は大きかった。

### 4.3 級内/級間比が精度を予測する

最終活性の**級内距離**(同じクラスの入力どうしのハミング距離の平均)と
**級間距離**(異なるクラスどうし)を測った(MNIST、seed=1、テスト集合、クラスあたり60件、総ビット1024)。

| 条件 | 級内 | 級間 | 級内/級間 | テスト精度 |
|---|---:|---:|---:|---:|
| `proto`(元のBEP) | **235.9** | 538.9 | **0.438** | **0.9055** |
| randall n=512 | 255.5 | 535.9 | 0.477 | 0.9004 |
| randall n=128 | 276.2 | 534.0 | 0.517 | 0.8908 |
| `diff` + 分類器学習 | 275.0 | 527.8 | 0.521 | 0.8950 |
| randdiff n=512 | 287.2 | 530.8 | 0.541 | 0.8911 |
| `diff` | 283.4 | 530.8 | 0.534 | 0.8911 |
| `diffgate` | 300.9 | 527.2 | 0.571 | 0.8820 |
| randdiff n=128 | 312.9 | 526.2 | 0.595 | 0.8850 |
| randall n=32 | 299.4 | 528.8 | 0.566 | 0.8675 |
| randdiff n=32 | 330.5 | 524.2 | 0.630 | 0.8665 |
| randall n=8 | 332.0 | 517.6 | 0.641 | 0.7551 |
| randdiff n=8 | 428.2 | 475.3 | **0.901** | **0.5023** |

**比が小さい(=クラスごとに1点へまとまっている)ほど精度が高い**という関係が強く出る。
ただし**順序は完全には一致しない。** 例えば randall n=128(比 0.517 / 精度 0.8908)は
`diff` + 分類器学習(比 0.521 / 精度 0.8950)より比が小さいのに精度は低い。
順位相関は Spearman で約 −0.93 であり、**強い相関だが完全な順序一致ではない**。

### 4.4 「選ばなかったビットから信号を送らない」忠実版(`-hard`)

`randdiff` の既定(soft)は、選ばれなかったビットに現在の活性を置く。
これは**最終層の重み更新からは外れるが、前段への後方射影には依然として参加する**
(そのビットは「今のままでいい」という信号を送る)。
提案の「誤差信号を送らない」に忠実なのは、ゲートからも外す `-hard` の方である。

MNIST、60エポック、seed=1:

| n | soft | hard(忠実版) |
|---|---:|---:|
| 32 | 0.8726 | 0.8724 |
| 128 | **0.8911** | 0.8799 |
| 512 | **0.8981** | 0.8877 |

n=512 の3シード:

| seed | soft | hard |
|---|---:|---:|
| 1 | **0.8981** | 0.8877 |
| 2 | **0.8950** | 0.8841 |
| 3 | **0.8964** | 0.8865 |
| 平均 | **0.8965** | 0.8861 |

**忠実版の方が悪い**(n=512 で −1.04pt、3シードすべて)。
n=32 では差がない。したがって「後方射影からも外す」ことに利点はない。

これは §3 の `diff -hard` の結果とも整合する。後方射影 `sign(Wᵀ(g⊙t))` は
ゲート内ビットの多数決なので、寄与するビットを減らすと投票がノイジーになる。
「今のままでいい」という信号が混じる害よりも、票数が減る害の方が大きい。

### 4.5 学習量の不足ではないか(収束させた比較)

n が小さいほど1エポックあたりの教師信号が少ないので、同じ20エポックでの比較は
n が小さい条件に不利ではないか、という懸念がある。実際、20エポックの実験では
n が小さい条件の多くが最終エポックで最良になっており、まだ改善途中に見えた。

そこでエポック数を増やして確かめた(MNIST、seed=1)。

| 条件 | 20ep | 60ep | 200ep | 640ep | 級内/級間の推移 |
|---|---:|---:|---:|---:|---|
| `proto`(元のBEP) | 0.9055 | 0.9078 | **0.9106** | — | 0.438 → 0.431 → 0.416 |
| randdiff n=32 soft | 0.8665 | 0.8726 | 0.8780 | 0.8825 | 0.630 → 0.611 → 0.611 → 0.623 |

**エポックを32倍にしても追いつかない。** 640エポックは
「1サンプルあたりの総指定ビット数」を `proto` の20エポックと揃えた条件だが
(32 × 640 = 1024 × 20)、それでも 0.8825 対 0.9055 で 2.3pt 及ばない。

より重要なのは**級内/級間比が 0.61 前後で頭打ちになる**ことである。
`proto` は 0.438 → 0.416 と改善し続けるのに対し、n=32 は改善しない。
つまり n=32 は「収束が遅いだけ」ではなく、**より拡散した表現へ収束している**。

なお `proto` 自身も200エポック時点で最良エポックが192であり、まだ改善余地がある。
差が縮まる兆候はない。

### 4.6 なぜ「差分から選ぶ」が不利になるのか(仮説)

対照(全ビットから無作為)では、どのビットも**競合クラスが誰かに関わらず**
一様に `P_y` へ押される。同じクラスの入力は同じ符号へ集まっていく。

一方、競合差分では**指定されるビット集合が競合クラス `r` に依存する**。
`r` はサンプルごとに変わるため、あるクラスの入力でも押し込まれる先が揃わない。
よく競合する相手と `P_y` が一致するビットは、いつまでも指定されないまま残る。

つまり「判別に無関係なビットは更新しても点数差が変わらない」という指摘は正しいが、
**そのビットの更新は点数差ではなく級内凝集に効いていた**。
凝集が崩れるとロジットの分散が増え、結果的に判別が悪化する。

**これは §4.3 の相関に基づく解釈であり、因果を直接示したものではない。**

## 5. 整数読み出しとの関係

この結果は、整数読み出しがなぜ効いたのかも説明する。

- `proto` 目標 + プロトタイプ読み出し = **表現を凝集させて、単純な読み出しで読む**
- 拡散した表現 + 整数読み出し = **凝集させない代わりに、賢い読み出しで読む**

`../nnlab/REPORT.md` §2.3 の測定(BEPのバックボーンの読み出しだけ整数線形に替えると、
幅8192で +4.73pt)は後者に当たる。整数読み出しは、級内が拡散していても
「どのビットがどのクラスにどれだけ効くか」を学ぶので、凝集を必要としない。

本フォルダで試した案はすべて**目標を緩めておきながら読み出しは単純なまま**なので、
両方の利点を失う位置に来てしまった、というのが一連の結果の読み方である。

したがって END-TO-END を保ちたい場合、進む方向は「目標を緩める」ではなく、
**凝集を保ったまま、読み出し側の表現力を二値のまま上げること**だと考えられる。
例えば `../UNIVERSAL_APPROXIMATION.md` §5.1 の重み複製(クラスごとに m 本の二値行を持ち、
票を合計する)なら、可視重みは ±1 のままで実効的に整数重み相当の表現力が得られ、
推論も popcount のままである。**これは未実施の提案であり、本報告では検証していない。**

## 6. 制約・注意

- 分類のみ。回帰(温度計プロトタイプ)では未検証
- §4.5 の収束比較と §4.1 の n 掃引は seed=1 のみ
- 3シード。差の大きい条件(n=8 の崩壊、`diff` の −1.11pt、`-hard` の −1.04pt)は
  ばらつきを超えるが、
  `learnq` 単独の影響(−0.11pt)や §4.2 の 0.3〜0.7pt 級の差は
  **示唆であって確定ではない**(3シードの「3/3同方向」は符号検定で p≈0.125 相当)
- §4.3 の診断は seed=1・MNIST のみ。**相関であって因果を直接示したものではない**
- 分類器の学習率は `clslr = 0.1` 固定。バックボーンと分けた掃引はしていない
- 分類器の更新則は「正解行を活性へ、競合行を活性から」のみ。
  マージンや疎化(BEPのグループ選択に相当するもの)は入れていない
- n の掃引は seed=1 のみ。3シードで確認したのは n ∈ {128, 512} だけ
- §5 の重み複製案は未実施
