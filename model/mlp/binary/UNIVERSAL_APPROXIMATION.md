# ビット・整数BEPに万能近似性を持たせるための設計要件

## 1. この文書の位置づけ

この文書は、現在の `binary` パッケージが既に万能近似性を持つと主張するものではない。
BEPの中核である次の性質を保ちながら、万能近似性を持つ**モデル族**へ拡張するための設計要件をまとめたものである。

- 可視重みと活性は二値
- 順伝播と誤差信号の逆伝播は、主にXNOR、popcount、ビット走査で実行
- 学習用の隠れ重みは小さな符号付き整数
- 学習から推論まで、浮動小数点演算を必須にしない
- 二値で表現できない量は、固定小数点整数、整数カウンタ、整数比較で扱う

ここでいう万能近似性は、1個の固定サイズモデルが全関数を近似するという意味ではない。
入力精度、出力精度、層幅を必要に応じて増やせるモデル族について、次を満たすことを目標とする。
以下、`R^r` 上の誤差にはmaxノルム `||v||_infinity = max_k |v_k|` を使う。

> コンパクト集合 `K` 上の任意の連続関数 `f: K -> R^r` と任意の `epsilon > 0` に対し、
> 有限サイズのモデル `F` が存在して、`sup_(x in K) ||F(x) - f(x)||_infinity < epsilon` にできる。

古典的な万能近似定理の対象は「任意の関数」ではなく、通常はコンパクト集合上の連続関数である。
有限の二値入力上では、任意の写像を正確に表現することを別途目標にできる。

## 2. 先に結論

次の変更をすべて許せば、ビット演算と軽量整数演算だけからなるモデル族に万能近似性を持たせられる。

1. 入力を、要求精度に応じて細かくできる固定小数点・二値符号へ変換する
2. 各Dense層の各ニューロンに、符号付き整数バイアスを持たせる
3. 層幅を要求精度に応じて増やせるようにする
4. 回帰出力を、要求精度に応じてビット数を増やせる固定小数点値として表現する
5. バイアスと活性前値を保持する整数型幅を、モデル規模に応じて増やせるようにする
6. 現在の学習・推論経路に残っている浮動小数点の確率、マージン、ノイズ、値表現を整数化する

定数1を入力に何個追加しても、入力符号長と出力精度を固定したままでは万能近似性は得られない。
定数1が増やすのはバイアスの表現範囲だけであり、入力二値化で失われた情報や、有限出力の量子化誤差は回復しないためである。

## 3. 現在のモデルと不足している条件

BEP論文の二値バックボーンは、層 `l` について概ね次で定義される。

```text
W_l = sign(H_l)
z_l = W_l a_(l-1)
a_l = sign(z_l)
```

- `H_l`: 整数の隠れ重み
- `W_l`: `{-1, +1}` の可視重み
- `a_l`: `{-1, +1}` の活性

現在の実装も、XNOR相当の一致数 `count` から次を計算している。

```text
z = 2 * count - fanIn
```

一方、現行実装には以下の制約がある。

- Dense層に明示的なバイアスがない
- 入力符号長 `XRows * XCols` はモデルごとに固定
- 回帰値 `Values` は有限個の `float32`
- `PredictValue` は最大logitに対応する `Values` を返し、同点時は該当する複数値の平均を返すため、出力集合は有限だが `Values` にない値も返し得る
- `PredictSoftmax` は指数関数と浮動小数点を使う
- 学習率、マージン、ノイズ尺度、ゲート尺度に浮動小数点が残っている
- 固定された有限サイズのモデルでは、入力状態も出力状態も有限個

したがって、現在の固定モデルに定数1だけを追加しても、古典的な万能近似定理の前提は満たさない。

## 4. 万能近似性の構成

以下ではまずスカラー値関数 `f: K -> R` について構成する。
多出力関数 `f: K -> R^r` では、有限個の各出力成分をそれぞれ `epsilon` 未満で近似し、出力ビット列を連結すれば、maxノルムでの誤差も `epsilon` 未満になる。

### 4.1 連続入力を有限精度の整数へ変換する

`K` をコンパクト集合、`f: K -> R` を連続関数とする。
コンパクト集合上の連続関数は一様連続なので、任意の `epsilon > 0` に対し、十分小さい `delta > 0` を選んで次を満たせる。

```text
||x - y|| < delta なら |f(x) - f(y)| < epsilon / 2
```

入力空間を直径 `delta` 未満の有限個のセルに分割し、各セルを有限ビットの符号へ変換する。
符号化関数は各セル上で定数とし、同一セルに属する入力は必ず同一の二値符号へ写す。
これにより、連続入力の近似問題を、4.2で扱う有限二値入力上の写像へ接続できる。
実装では、入力を固定小数点整数として保持し、2の冪の幅を持つ格子、温度計符号、または同等の整数比較だけで作れる符号を使う。

重要な点は、入力ビット数を固定しないことである。
要求誤差を小さくするほど、入力の小数部ビット数または温度計符号長を増やす。

生の入力が浮動小数点でしか与えられない場合、その値を固定小数点整数へ変換する境界処理は必要になる。
「学習から推論まで浮動小数点を使わない」を厳密に満たす場合は、学習データと推論入力を最初から固定小数点整数で保存し、入力エンコーダーも整数演算で実装する。

### 4.2 二値入力上の任意写像を二値しきい値回路で表す

入力を `x in {-1, +1}^d` とする。入力パターン `p in {-1, +1}^d` 専用の検出ニューロンを次で作る。

```text
h_p(x) = sign(p^T x - (d - 1))
```

`x = p` のとき `p^T x = d` なので `h_p(x) = +1` になる。
1ビットでも異なると `p^T x <= d - 2` なので `h_p(x) = -1` になる。

全 `2^d` パターンに1個ずつ検出ニューロンを用意すれば、有限二値入力を完全に識別できる。
これは効率的な構成ではないが、表現能力の存在証明として使える。

入力エンコーダーが有限の有効コード集合 `C subseteq {-1, +1}^d` だけを生成する場合、検出ニューロンは `p in C` に対してだけ用意すればよい。
上の検出式は `C` 内の異なるコードも正確に識別でき、以下の和を `C` 上で取れば同じ証明が成立する。
したがって、温度計符号のように無効なビット列が多い符号について、常に全 `2^d` パターンを列挙する必要はない。

出力ビット `k` の正解を、入力パターン `p` ごとに `y_(p,k) in {-1, +1}` とする。
検出ニューロンから出力 `k` への重みを `y_(p,k)` とし、次の整数バイアスを置く。

```text
S_k = sum_p y_(p,k)
```

入力 `p` に対する出力の活性前整数は、次になる。

```text
2 * y_(p,k) - S_k + S_k = 2 * y_(p,k)
```

よって出力符号は正確に `y_(p,k)` となる。
したがって、二値重み、二値活性、整数バイアスだけで、有限二値入力から有限ビット出力への任意写像を正確に表現できる。

`C` 限定構成では、上の `S_k` と出力層の和を `C` 上で取る。
一方、`x not in C` では全検出ニューロンが `-1` になるため、出力 `k` の活性前整数は `-S_k + S_k = 0` になる。
したがって、この縮小構成が任意写像を保証する範囲は `C` 上だけである。
現在の実装は `sign(0) = +1` なので、`C` 外では全出力ビットが `+1` になるが、これは対象写像の保証ではなく符号規約による既定動作である。
入力経路は `C` 外のコードを生成しないことを検証し、外部から符号を直接受け取るAPIでは無効コードを拒否するか、`C` 外の動作を別途定義する。

この読み出し部は、後述するYayla et al.のTheorem 2そのものではない。
同定理は入力ごとの検出ニューロンにしきい値 `d - 1` を使う点では共通するが、出力層の実数重みを連立方程式 `Aw = b` で決める。
本節は、その実数読み出しを、二値出力重みと整数バイアス `S_k` による多ビット読み出しへ置き換えた独自の構成である。

この構成の幅は最悪 `2^d` である。
万能近似性は存在を保証するだけで、パラメータ効率を保証しない。

### 4.3 出力を固定小数点にする

出力に小数部 `F` ビットを持たせ、整数 `Q` を次の実数として解釈する。

```text
y = Q * 2^(-F)
```

内部で保存・計算するのは整数 `Q` と整数 `F` だけである。
`2^(-F)` は暗黙の尺度であり、ネットワーク内部で浮動小数点を計算する必要はない。

各入力セルの代表点 `x_c` に対し、次の整数を出力する。

```text
Q_c = round(f(x_c) * 2^F)
```

また、`f` はコンパクト集合上で連続なので有界であり、`M = sup_(x in K) |f(x)| < infinity` と置ける。
丸め分を含めても `|Q_c| <= M * 2^F + 1` と上から抑えられるので、符号と整数部を含む必要ビット数には、例えば次の上界を使える。

```text
requiredBits <= F + 2 + ceil(log2(M + 1))
```

したがって、固定した値域では必要ビット数は `F` に対して線形に増える。
実装では小数部の `FractionBits` だけでなく、この整数部と符号を保持できるRaw値の型幅もモデル設定から検証する。

`F` を十分大きくして出力量子化誤差を `epsilon / 2` 未満にすれば、入力セル内の誤差との和により次を得る。

```text
|f_hat(x) - f(x)| < epsilon
```

以上により、入力精度、層幅、整数バイアス、出力ビット数、ならびにそれらを安全に保持する整数型幅を要求誤差に応じて増やせるモデル族は、コンパクト集合上の連続関数を任意精度で近似できる。

### 4.4 固定ビット幅では万能近似にならない

入力ビット数、出力ビット数、層幅、整数型の範囲をすべて固定すると、モデルが区別できる状態数は有限になる。
そのため、単一の固定ハードウェア構成に対して `epsilon -> 0` を要求することはできない。

万能近似性は、各 `epsilon` に対して有限だが異なるモデルを選べるというモデル族の性質である。
必要な整数の**値**は大きくなる場合があるが、その値を保持するためのビット幅は対数的に増える。

ただし、4.2で全二値入力を列挙する直接構成では、出力層の `fanIn = 2^d` かつ `abs(S_k) <= 2^d` である。
5.1の一般的な上界を使うと、活性前値のアキュムレータに必要なビット幅は入力符号長 `d` に対して線形に増える。
`int32` の正の最大値は `2^31 - 1` なので、この一般上界 `2^(d+1)` を満たせるのは `d <= 29` であり、`d = 30` では上界を超える。
したがって、5.1の `int32` は実用範囲向けの初期選択にすぎない。
万能近似性を主張するモデル族では、入力・出力精度や層幅とともに、バイアスと活性前値の整数型幅も増やせる必要がある。

## 5. 必要なモデル改変

### 5.1 各Dense層へ符号付き整数バイアスを追加する

推奨する順伝播は次である。

```text
z_(row,j) = 2 * matchCount_(row,j) - fanIn + Bias_j
a_(row,j) = sign(z_(row,j))
```

`Bias_j` は実用上の初期選択として `int32`、または事前に算出した範囲を満たす最小の符号付き整数型とする。
`preActivationMax` は、活性前整数のアキュムレータ型が `[-preActivationMax, preActivationMax]` の全整数を安全に表現できる最大の非負整数とする。
`maxAbsNoise` は、その層で活性前整数へ加算し得る整数ノイズの絶対値上界とし、ノイズを使わない推論では `0` とする。
`fanIn`、`preActivationMax`、`maxAbsNoise` は層ごとに定め、5.1では読みやすさのため層添字 `_l` を省略し、5.2では明示する。
加算器のオーバーフローを防ぐため、次を検証する。

```text
abs(Bias_j) + fanIn <= preActivationMax
```

これはノイズを加えない推論経路の上界である。
現在の学習時 `Forward` と同様に、ノイズを `[-fanIn, fanIn]` の範囲で加える場合は、より強い次の条件が必要になる。

```text
abs(Bias_j) + 2 * fanIn <= preActivationMax
```

実際の整数ノイズの範囲を変更する場合は、一般に `abs(Bias_j) + fanIn + maxAbsNoise` を検証する。

バイアスは全層に必要である。
元の入力にだけ定数1を追加しても、直接のバイアスになるのは第1層だけである。

#### 定数1を並べる方式との関係

定数1を `m` 個追加し、それぞれに二値重み `beta_k` を持たせると、実効バイアスは次になる。

```text
Bias = sum_k beta_k
beta_k in {-1, +1}
```

この方式で表現できる値は `{m, m - 2, ..., -m}` であり、`m` と同じパリティの整数に限られる。
必要なバイアスとパリティが異なる場合は、定数入力数を奇数個分変えてパリティを合わせる。
パリティを保ったまま定数入力数だけを増やす場合は、重みが `+1` と `-1` の相殺用定数対を追加できる。

これはビット演算だけで実現できるが、バイアスの絶対値に比例して入力幅と隠れ重みが増える。
推論効率を優先する場合は、その和を1個の整数 `Bias` として直接保持する。

ただし、複数のバイアス用シナプスを1個の整数へ圧縮すると、各シナプスが持っていた個別のメタ可塑性は失われる。
定数シナプス方式と整数バイアス方式で学習ダイナミクスが同一とは限らないため、これは実験で比較する。

### 5.2 BEPの誤差伝播へ整数バイアスを統合する

順伝播とゲート判定では、必ずバイアス込みの活性前整数を使う。

```text
z_l = W_l a_(l-1) + b_l
g_(l,i) = 1[abs(z_(l,i)) <= threshold_l]
```

希望活性の後方伝播は、次のまま使える。

```text
a_l* = sign(W_(l+1)^T (g_(l+1) odot a_(l+1)*))
```

`b_(l+1)` は `a_l` に依存しない加算項なので、`a_l` の希望方向を求める逆射影には現れない。
ただし `b_(l+1)` は `z_(l+1)` を変えるため、ゲートには間接的に効く。

整数バイアスを直接学習する場合、選択されたニューロンについて、現行実装の集約後符号化に合わせた候補更新は次のような整数加減算にできる。

```text
sampleDeltaBias_(mu,l,j) = a*_(mu,l,j)
Mask_(mu,l,j) in {0, 1}
rawAggregatedDeltaBias_(l,j) = sum_mu (Mask_(mu,l,j) * sampleDeltaBias_(mu,l,j))
aggregatedDeltaBias_(l,j) = sign(rawAggregatedDeltaBias_(l,j))
BMax_l = preActivationMax_l - fanIn_l - maxAbsNoise_l
Bias_(l,j) <- clip(Bias_(l,j) + 2 * aggregatedDeltaBias_(l,j), -BMax_l, BMax_l)
```

`Mask_(mu,l,j)` は、サンプル `mu` に対する現在のスパース更新対象選択を表す。
ここで `BMax_l >= 0` をモデル検証時に確認する。
`clip` の範囲は整数型そのものの上下限ではなく、5.1のオーバーフロー条件から導いた範囲である。

係数2はBEP論文の隠れ重み更新と1回の更新幅を合わせる場合の候補である。
ただし、BEP論文Eq.9はサンプル差分の生の総和を使う一方、現行実装は `Aggregate` の後に `Sign` を適用して各差分を `{-1, 0, +1}` に潰す。
バイアス差分もこの経路へ統合すると、確率的学習率によるスキップ前のバイアス更新幅は、各ニューロンについて1バッチあたり最大 `+2` または `-2` に制限される。
4.2で必要になり得る大きな `S_k` への到達が遅くなる可能性があるため、生の総和を保持する更新則との比較が必要である。
生の総和を使う場合は、差分アキュムレータの型幅と、1回の更新後にも `BMax_l` を守るクリップを別途検証する。
実際には、現在のスパースマスク、バッチ集約、確率的学習率と整合するように更新対象を制限する。
このバイアス更新則の学習性能と安定性は、万能近似性の存在証明とは別に検証する。

### 5.3 入力エンコーダーを可変精度にする

入力エンコーダーは、モデル設定に次を保持する。

- 入力の整数尺度または小数部ビット数
- 各次元の有効範囲
- 量子化セル幅
- 二値符号方式

小規模な理論・互換性検証の最初の実装候補は、現在の回帰用プロトタイプと相性がよい温度計符号である。
ただし「精度」を量子化段階数 `L` と小数部精度 `F` のどちらで測るかを区別する必要がある。
温度計符号長は `Theta(L)` なので段階数には線形だが、固定値域で `F` ビット相当の精度を得るには `L = Theta(2^F)` となり、符号長は `Theta(2^F)` である。
二進符号またはGray符号なら同じ段階数を `Theta(log L) = Theta(F)` ビットで表せる。

4.2を全 `d` ビット列へ機械的に適用すると、温度計では `2^d = 2^(Theta(2^F))` という二重指数の上界になる。
しかし、温度計エンコーダーが実際に生成する有効コード集合 `C` だけに検出器を用意すれば、幅は `2^d` ではなく `|C|` でよく、この人工的な二重指数は避けられる。
各量子化セルへ異なるコードを割り当てる限り、`C` 限定版4.2の検出器数は符号化方式によらずセル数 `|C|` そのものである。
符号化方式の選択が直接変えるのは、主に符号長 `d`、各検出器のファンイン、ビット走査量である。
それでも入力符号自体の長さとXNOR・popcountのコストは `Theta(2^F)` なので、温度計は小規模な理論・互換性検証用とし、可変精度入力の本命は二進符号またはGray符号とする。

入力前処理で浮動小数点を使わないため、セル境界を2の冪にそろえ、整数の減算、比較、シフトで符号化できるようにする。

### 5.4 回帰出力を可変精度の整数へ変更する

最小変更案は、現在のプロトタイプ方式を残し、`Values []float32` をモデル共通の尺度を持つ整数値へ変更することである。

概念上は次のような表現になる。

```text
type FixedValues struct {
    Raw          []int64
    FractionBits uint8
}
```

`Raw[i]` の実数としての意味は `Raw[i] * 2^(-FractionBits)` である。
学習・推論内部では `Raw[i]` だけを扱う。
`FractionBits` に加え、4.3で示した値域の整数部と符号を格納できるRaw値の型幅も可変または事前検証可能にする。

可変精度の本経路として、最終活性をそのまま符号付き固定小数点のビット列にし、整数へデコードする多ビット出力ヘッドを設ける。
この方式では、ビット重み `2^k` は乗算せず、シフトとORまたは加算で復号できる。
固定した値域に対して小数部精度を `F` ビット増やすコストは、整数部と符号を除けば出力ビット数 `F` に対して線形である。

多ビット出力ヘッドでは、要求誤差と値域に応じて次を増やせる必要がある。

- `FractionBits`
- 整数部と符号を含むRaw値の型幅
- 最終活性の出力ビット数

現在のプロトタイプ方式を採る場合は、これらに代えて、または加えて次を増やせる必要がある。

- `Values` の段階数
- 出力プロトタイプ長

現在のBEPとの近さを優先する互換性検証では、出力を温度計符号プロトタイプとし、popcountで整数レベルへ戻す方式が扱いやすい。
温度計符号は、`n` 個の異なる段階を表すために少なくとも `n - 1` ビットを要する。
固定した値域で小数部 `F` ビット相当の精度を得るには `n = Theta(2^F)` 段階が必要なので、出力幅も `Theta(2^F)` となる。
隣接値のハミング距離が安定して既存の学習則と整合しやすい利点はあるが、4.3の可変精度出力を実用的な計算量で担う本命は多ビット出力ヘッドとする。
温度計方式は小規模な互換性実験および学習則の比較対象と位置づける。

### 5.5 層幅を固定しない

万能近似性は、幅を必要に応じて増やせることを前提とする。
二値入力上の単純な存在証明では、入力ビット数 `d` に対して最悪 `2^d` 個のパターン検出ニューロンを使う。

実用モデルがこの指数幅を採用する必要はない。
深さ、入力符号の構造、問題固有の規則性を使って圧縮できる可能性がある。
ただし「現在の幅のまま万能近似」とは主張しない。

## 6. 学習から推論まで浮動小数点を除くための変更

万能近似性とは独立に、現在の `binary` パッケージには浮動小数点が残っている。
「学習から推論までビット・整数だけ」を厳密に満たすには、少なくとも以下を変更する。

| 現在の要素 | 問題 | 整数化案 |
|---|---|---|
| `Trainer.LR float32` | 確率判定に浮動小数点を使う | `uint64` 乱数との比較しきい値、または `numerator / 2^shift` |
| `Trainer.Margin float32` | 更新判定に浮動小数点を使う | 有理数 `numerator / denominator`、または固定小数点 |
| `GateDropThresholdScale float32` | ゲート閾値計算が浮動小数点 | 最終的な整数閾値を直接保持、または有理数尺度 |
| `NoiseStdScale float32` | ノイズ尺度と生成が浮動小数点 | 整数離散ノイズ、整数LUT、整数一様乱数の和 |
| `NoiseStdBase` の平方根 | 初期化で浮動小数点 | 整数平方根 |
| ゲート用 `absZi` | `math.Abs(float64(zi))` で整数を一度浮動小数点へ変換 | 整数の符号分岐で絶対値を求め、最小負数を扱える広い整数型を使う |
| `Values []float32` | 回帰出力が浮動小数点 | 共通尺度を持つ `[]int64` 固定小数点 |
| `SetValues` の値間隔 | `float32` の除算と乗算を使う | 固定小数点Raw値を整数除算で生成し、丸め規約を明示 |
| `SetClassPrototypes` の反復回数 | `math.Log` を使う | 整数で反復回数を直接指定、または整数bit lengthで上界を計算 |
| `SetRegressionHighPrototypes` | `sigma float32` とRFF生成が浮動小数点に依存 | 厳密整数経路から外すか、温度計・整数乱数ベースのプロトタイプへ置換 |
| `PredictSoftmax` | `exp` と除算が浮動小数点 | 厳密な整数経路から外し、推論は整数logitのargmaxを使う |
| `Loss` | 二乗誤差が浮動小数点 | 固定小数点差の整数二乗と広い整数アキュムレータ |
| `PairwiseLabels` のmargin | 値域との積が浮動小数点 | 固定小数点値と有理数marginの整数比較 |
| `SplitTrainValidation` の比率 | データ分割に浮動小数点 | 個数または有理数で指定 |
| 探索・精度表示 | 指標が浮動小数点 | 学習本体から分離するか、分数の分子・分母で保持 |

乱数そのものは整数PRNGで生成する。
確率 `p` は、例えば `T = floor(p * 2^64)` を設定時に整数として与え、`rng.Uint64() < T` で判定できる。
設定ファイルから小数を読む場合も、10進文字列を整数の分子・分母へ変換すれば浮動小数点は不要である。

評価レポートやUI表示だけで浮動小数点へ変換することは、学習・推論カーネルの制約とは分離できる。
完全に禁止する場合は、表示も整数の商と余りで整形する。

## 7. BEP学習則と万能近似性を混同しない

万能近似定理が保証するのは、指定誤差を達成するパラメータが**存在すること**である。
次は保証しない。

- BEPが有限時間でそのパラメータを発見すること
- 現在の初期値、ノイズ、ゲート、スパース更新で収束すること
- 必要なモデル幅が実用的であること
- 学習データが有限でも未知入力へ汎化すること

そのため、実装では次を分けて検証する。

1. **表現能力検証**: 真理値表やセルごとの目標値から重みとバイアスを直接構成し、任意写像を表現できることを確認
2. **学習能力検証**: 同じ問題をBEP更新だけで学習できるか測定

表現能力検証が成功し、学習が失敗した場合、問題は万能近似性ではなく最適化・学習則にある。

## 8. 推奨する実装順序

### 段階1: 整数バイアス付きDense

- `Dense` にニューロンごとの整数バイアスを追加
- `Forward` と `Predict` の `z` に加算
- `Forward` と `Predict` が共有する活性前整数の計算を非公開の共通経路へ分離し、`package binary` の内部テストから `z` を直接検証できるようにする。テスト目的だけの公開APIは追加しない
- ゲートと更新対象選択がバイアス込み `z` を使うよう変更
- バイアスを全層で使えることをテスト
- 5.1の上界からバイアスのclip範囲を導き、オーバーフロー検証を追加
- 集約後符号化と生の総和を使うバイアス更新を比較できるようにする

### 段階2: 有限二値写像の構成テスト

- 小さい `d` について全 `2^d` 入力を列挙し、全二値入力版4.2の式から重みとバイアスを直接構築
- 全二値入力版がランダムな多ビット真理値表を全件正確に再現し、各出力の活性前整数が `2 * y_(p,k)` になることをテスト
- 温度計符号などから真部分集合 `C` を作り、`C` 上だけに検出器を置く縮小構成をテスト
- 縮小構成では、`C` 上で任意写像と活性前整数 `2 * y_(p,k)` を正確に再現し、`C` 外では全出力の活性前整数が `0`、現在の `sign(0)` 規約による出力が全ビット `+1` になることを全 `2^d` 入力で確認
- この段階ではBEPによる学習を要求しない

### 段階3: 回帰値の固定小数点化

- `Values` と関連APIを整数＋共通尺度へ移行
- `PredictValue`、`Loss`、pairwise処理を整数化
- `PredictSoftmax` を厳密整数経路から除外
- 可変精度の本経路として多ビット出力ヘッドを追加し、温度計方式は比較対象とする
- 小数部だけでなく整数部と符号を含むRaw値の型幅を検証
- 保存形式の互換性方針を決める

### 段階4: 学習ハイパーパラメータの整数化

- 学習率とマージンを有理数化
- ゲート閾値を整数化
- ノイズを整数離散分布へ変更
- ゲート判定の `math.Abs(float64(zi))` を整数絶対値へ変更
- 学習中に浮動小数点命令が不要であることを監査

### 段階5: 可変精度入力と近似誤差テスト

- 固定小数点入力エンコーダーを追加
- エンコーダーが有効コード集合 `C` の外を生成しないことをテストし、直接入力APIの無効コード方針を決める
- `f(x) = x`、`x^2`、区間上のLipschitz関数等で構成的近似を作る
- 入出力精度を増やすと最大誤差が所定の上界以下へ減ることをテスト
- 多次元の小規模例でもセル識別を確認

### 段階6: BEPでの学習実験

- 整数バイアスの更新則を比較
- 温度計出力と二進固定小数点出力を比較
- 表現可能だが学習できない例を記録
- 幅、深さ、ゲート、ノイズ、バイアス範囲の影響を測定

## 9. 完了条件

「ビット・整数BEPが万能近似性を持つ」とプロジェクト内で主張する前に、少なくとも次を満たす。

- 対象関数を「コンパクト集合上の連続関数」と明記している
- 任意の `epsilon > 0` に対する構成または証明がある
- 入力精度、出力精度、幅が `epsilon` に依存して増えることを明記している
- 二値入力上の任意写像を構成する自動テストがある
- 有効コード集合 `C` 上の縮小構成を使う場合、入力経路が `C` 外のコードを生成しないことを自動テストしている
- 固定小数点の量子化誤差上界を自動テストしている
- 学習・推論の必須経路に `float32`、`float64`、`math.Exp` がない
- XNOR、popcount、整数加算、整数比較、シフトだけで推論できる
- BEP学習の成功を万能近似定理の一部として誤記していない
- 固定サイズの1モデルに万能性があると誤記していない
- 整数オーバーフローの上界をモデル検証時に確認している

## 10. 根拠資料

### BEP

- Luca Colombo et al., "BEP: A Binary Error Propagation Algorithm for Binary Neural Networks Training"
  - arXiv abstract: https://arxiv.org/abs/2512.04189
  - arXiv PDF: https://arxiv.org/pdf/2512.04189
  - ローカル: `papers/2512.04189v2.pdf`
- 本文Section 3では、二値可視重み、二値活性、整数隠れ重み、希望活性の二値逆伝播、Hebbian外積更新を定義している。
- BEP論文は学習則を与えるが、この `binary` 実装へ整数バイアスと可変精度出力を追加したモデルの万能近似性や、BEPの収束を証明してはいない。

### Fully Connected BNNの万能近似定理

- Mikail Yayla, Mario Guenzel, Burim Ramosaj, Jian-Jia Chen,
  "Universal Approximation Theorems of Fully Connected Binarized Neural Networks"
  - arXiv abstract: https://arxiv.org/abs/2102.02631
  - arXiv PDF: https://arxiv.org/pdf/2102.02631
- Theorem 2: 二値入力では、1隠れ層の完全結合BNNで実数値写像を構成できる。証明は入力ごとの検出ニューロンとしきい値 `d - 1` を使い、出力層では実数重み `w` を連立方程式 `Aw = b` で決める。
- Theorem 5: 実数入力上のLipschitz連続関数について、2隠れ層の完全結合BNNに万能近似性がある。
- Theorem 6: 実数出力重みを、有理数スケールとニューロン複製を伴う二値出力重みで近似できる。
- Theorem 5の第1層は実数入力との通常の積和を含む。そのため、学習・推論をすべてビット・整数にする本設計では、同定理をそのまま実装するのではなく、固定小数点入力の有限セル化と、二値入力上の任意写像の構成を組み合わせる。
- 本文4.2はTheorem 2の入力検出部を参考にするが、同定理の実数出力重みは使わない。多ビット出力ごとに二値重みと整数バイアスを置く別構成である。
- Theorem 6の有理数スケールは、分母を2の冪に限定した固定小数点近似へ置き換えれば、整数とシフトで実装できる。これは同論文の証明をそのまま再実装するという意味ではなく、本設計の演算制約に合わせた構成である。

### 古典的な万能近似定理とバイアス

- George Cybenko, "Approximation by Superpositions of a Sigmoidal Function"
  - DOI: https://doi.org/10.1007/BF02551274
- Moshe Leshno, Vladimir Ya. Lin, Allan Pinkus, Shimon Schocken,
  "Multilayer Feedforward Networks with a Nonpolynomial Activation Function Can Approximate Any Function"
  - DOI: https://doi.org/10.1016/S0893-6080(05)80131-5
  - PDF copy: https://pinkus.net.technion.ac.il/files/2021/02/neural.pdf
- 古典的な結果は自由な実数重み、しきい値またはバイアス、実数出力係数を持つモデル族を扱う。
  定数1を入力へ追加する方法が通常のバイアスと等価なのは、その定数へ接続する重みが自由な実数 `b` を取れる場合である。
  二値重み1本ではバイアスが `{-1, +1}` に限られるため、古典的な定理をそのまま適用できない。

## 11. 最終的な判断

BEPの中核である二値可視重み、二値活性、ビット単位の誤差伝播、整数隠れ重みを保ったまま、万能近似性を持つモデル族は構成できる。
必要なのは浮動小数点の導入ではなく、次である。

- 全層の整数バイアス
- 可変精度の固定小数点入力
- 可変幅の二値バックボーン
- 可変精度の固定小数点出力
- モデル規模に応じて可変なバイアス・活性前値の整数型幅
- 学習確率、マージン、ゲート、ノイズの整数化

ただし、これらを実装してもBEPが任意の対象関数を実際に学習できるとは限らない。
表現能力の証明、構成的な正解パラメータのテスト、BEPによる学習実験を分離して進める。

## 12. この文書を運用するときの温度感

1〜11章は技術的な要件を述べたものである。
この章は、それらを実装・変更する際に、どこまでを厳密に守り、どこから先は許容するかという判断の基準を述べる。
個別の要件をどう適用すべきか迷ったときは、この章の意図に照らして判断する。

### 12.1 守りたいこと

BEPの価値は、重みも活性も二値であり、順伝播と誤差伝播がビット演算と軽量整数演算だけで完結する点にある。
したがって、**浮動小数点が中核に入り込むことは認めない**。
ここでいう中核とは、おおよそ次のものを指す。

- モデルのパラメータそのもの（可視重み、隠れ重み、バイアス）
- 推論の判定に使う量（活性前値、しきい値、ロジット、出力値の表現）
- 学習の更新則が依存する量（更新方向、更新幅、更新確率、マージン、ノイズ尺度、ゲート閾値）

これらが浮動小数点の値でなければ成り立たない設計になった時点で、BEPを使う理由が失われる。
また、万能近似性を満たすために浮動小数点を導入する必要は、4章のとおり存在しない。
「万能近似性のために小数が要る」という結論が出た場合は、その導出のどこかが誤っている。

### 12.2 許容すること

一方、次のものは中核ではない。厳密性を理由に作業を止める必要はない。

- 結果として整数を得るためだけに、途中で浮動小数点を経由する演算
- 評価レポート、精度表示、ハイパーパラメータ探索の記録など、学習・推論カーネルの外側
- 学習開始前に一度だけ行う設定値の算出

例として、6章の表にあるゲート判定の `absZi` は、整数を `float64` へ往復させているだけで値は厳密であり、
浮動小数点の値表現がモデルに入るわけではないため、中核の違反ではない。
ただし、これはビット単位の最内ループに置かれた型変換であり、
`if zi < 0 { zi = -zi }` のような**条件分岐による整数の絶対値へ置き換えて最適化する**。
これは純度のためではなく、速度と、FPUを持たない実行環境への移植性のための変更である。

### 12.3 中核かどうか判断できないときは報告する

何が中核に当たるかを機械的に線引きすることはできない。
この文書に従って作業する際、ある実装・変更が中核に当たるかどうかを判断できない場合は、
独自に判断して進めず、状況と選択肢を人間へ報告する。

特に次の場合は、実施前に必ず報告する。

- 中核に浮動小数点を導入しなければ実現できない、と判断した場合
- 中核か否かの解釈によって、設計または実装の結論が変わる場合
- 1〜11章の要件どうしが矛盾していると見える場合
- 6章の表にある項目について、整数化案では要求を満たせないと判断した場合
