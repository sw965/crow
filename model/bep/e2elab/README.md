# e2elab — 固定プロトタイプからバックボーンへ送る学習信号を変える実験

「後付けの整数読み出しは使いたくない。最後まで二値ネット自身が表現を作り学習してほしい」
という要望(2026-08-14)から始まった一連の検証。

BEP は最終活性へ固定プロトタイプ `P_y` の完全再現を要求するが、分類に本当に必要なのは
`P_y·a > P_c·a (c≠y)` だけである。この「過剰な厳しさ」を緩められないか、を2段階で試した。

- **実験A**: 出力分類器を学習可能な二値層にする(ETF初期値)+ 目標を「正解と最大競合の差」に
- **実験B**: 分類器は固定したまま、目標を指定するビットを絞る
  (競合差分の全ビット / 競合差分から n 個 / 全ビットから n 個)

推論経路は最後まで二値活性・二値可視重み・XNOR・popcount・整数比較だけで、
整数読み出しは存在しない。

## 結果: どの案も元の BEP を上回らなかった

3シード、検証分離、テストは選択に不使用。

| 条件 | MNIST | Fashion |
|---|---:|---:|
| **元のBEP**(目標 = 全ビットの `P_y`) | **0.9041** | **0.8246** |
| 分類器のみ学習 | 0.9030 | 0.8226 |
| 対照: 全ビットから無作為512個 | 0.8990 | 0.8229 |
| 競合差分(全ビット、約512) | 0.8930 | 0.8209 |
| 提案: 競合差分から512個 | 0.8918 | 0.8196 |
| 対照: 全ビットから128個 | 0.8904 | 0.7966 |
| 提案: 競合差分から128個 | 0.8855 | 0.8027 |
| 競合差分 + ゲート除外 | 0.8790 | 0.8117 |

要点は4つ。

1. **信号を絞るほど単調に悪化する。** 指定ビット数 n を 8→32→128→512→全部 と増やすと
   精度も単調に上がる(MNIST: 0.5023 → 0.8665 → 0.8850 → 0.8911 → 0.9055)。
   **学習量の不足ではない**。n=32 をエポック32倍(640ep、総信号量を proto の20epと同じに)
   しても 0.8825 止まりで、級内/級間比が 0.61 前後で頭打ちになる
2. **「競合差分から選ぶ」ことに一貫した利点がない。** 同じ n 個でも MNIST では
   **全ビットからの無作為選択の方が勝つ**(n=128/512とも3/3)。Fashion の n=128 では逆。
   符号がデータセットと n で入れ替わる
3. **級内/級間比が精度と強く相関する**(Spearman 約 −0.93。順序の完全一致ではない)
4. **「選ばなかったビットから信号を送らない」の忠実版(`-hard`、後方射影からも除外)は
   さらに悪い**(n=512 で −1.04pt、3シードすべて)

## わかったこと

最終活性の級内距離(同じクラスの入力どうし)と級間距離を測ると、
**比が小さい(=クラスごとに1点へまとまっている)ほど精度が高い**傾向が強い
(Spearman 約 −0.93。ただし順序の完全一致ではない)。

| 条件 | 級内/級間 | 精度 |
|---|---:|---:|
| proto(元のBEP) | **0.438** | **0.9055** |
| randall n=512 | 0.477 | 0.9004 |
| randall n=128 | 0.517 | 0.8908 |
| 競合差分(全部) | 0.534 | 0.8911 |
| randdiff n=128 | 0.595 | 0.8850 |
| randdiff n=8 | **0.901** | **0.5023** |

> **BEP が「過剰に厳しい」符号再現を要求しているのは、欠陥ではなく機能している。**
> 全ビットを `P_y` へ揃えさせることが、同じクラスの入力の表現を1点へ凝集させており、
> プロトタイプ最近傍で読む限り、その凝集こそが精度を支えている。
> 「判別に無関係なビット」の更新は点数差には効かないが、**級内凝集には効いていた**。

競合差分が不利になるのは、**指定されるビット集合が競合クラス `r` に依存する**ためと考えられる。
`r` はサンプルごとに変わるので、同じクラスでも押し込まれる先が揃わない。
一方、全ビットからの無作為選択は `r` に依存せず、どのビットも一様に `P_y` へ押される。

なお、私が立てた「指定なしビットが後方射影を汚染している」という仮説は、
そのビットをゲートからも外す条件で**否定された**(外すとさらに悪化する)。

## 整数読み出しとの関係

- proto目標 + プロトタイプ読み出し = **表現を凝集させて、単純な読み出しで読む**
- 拡散した表現 + 整数読み出し = **凝集させない代わりに、賢い読み出しで読む**

本フォルダで試した案はすべて目標を緩めておきながら読み出しは単純なままなので、
両方の利点を失う位置に来てしまった。END-TO-END を保つなら、進む方向は
「目標を緩める」ではなく**凝集を保ったまま読み出し側の表現力を二値のまま上げる**ことだと
考えられる(例: `../UNIVERSAL_APPROXIMATION.md` §5.1 の重み複製。**未実施**)。

## 実行方法

```sh
# 実験A: 分類器の学習
go run . -target proto -learnq=false -epochs 20 -seed 1   # 元のBEP
go run . -target proto -learnq       -epochs 20 -seed 1   # 分類器だけ学習
go run . -target diff  -learnq       -epochs 20 -seed 1

# 実験B: 目標を指定するビットを絞る(分類器は固定)
go run . -target diff              -epochs 20 -seed 1   # 競合差分の全ビット
go run . -target randdiff -n 128   -epochs 20 -seed 1   # 競合差分から128個
go run . -target randall  -n 128   -epochs 20 -seed 1   # 全ビットから128個(対照)
go run . -target randdiff -n 128 -hard -epochs 60 -seed 1   # 忠実版(後方射影からも除外)
go run . -target randdiff -n 32  -epochs 640 -seed 1        # 総信号量を proto x 20ep と揃える
```

`-n` の代わりに `-q 0.1` のように母集団に対する割合でも指定できる。

## 注意

- **crow / omw のライブラリコードは変更していない。** BEPの順伝播・逆伝播・更新は
  `../biaslab` と同じ土台で、crow本体との1ステップ差分テストは `../biaslab/main_test.go` にある
- 分類のみ。回帰では未検証
- 3シード。n=8 の崩壊や競合差分の −1.11pt はばらつきを超えるが、
  0.3〜0.7pt 級の差は示唆であって確定ではない
- 級内/級間比の診断は seed=1・MNIST のみ。相関であって因果の直接証明ではない。
  なお比は**検証最良エポックのモデル**で測っている(精度と同じモデル)
- n の掃引と収束比較は seed=1 のみ。3シードで確認したのは
  n ∈ {128, 512} と hard/soft の比較だけ
- 競合クラスは学習時のノイズ入り活性から選んでいる。
  ノイズなし出力から選ぶ条件は未検証
