# 畳み込み(CNN)と、しきい値の正規化(研究メモ)

2026-09-25〜26 の実験の記録。crow 本体は変更しておらず、`model/bep` をスクラッチにコピーして試した(プログラムは残していない)。

**結論: CNN の部品(Im2Col・Flatten・GAP)も、しきい値の正規化(§4)も、crow には入れない。**
CNN は速度に対して利点が限られ(§3・§7)、正規化は分類では同等でも回帰の全結合で悪化した(§8)。
ここで見つかった「入力数が小さい層で既定の `MaxUpdateAbsZ`・`MarginAbsZ` が切り捨てで 0 になる」問題だけは、
正の倍率なら最低 1 にするよう crow の `absZForScale` を直した。
前提となる選び方(しきい値 `MaxUpdateAbsZ`・マージン `MarginAbsZ`、ノイズの廃止)は [UPDATE_SELECTION.md](UPDATE_SELECTION.md) を参照。

共通条件: 二値化 MNIST / Fashion-MNIST、ETF プロトタイプ(10 × 1024 ビット)、ミニバッチ 1024、`LRHalfPow` 3、`LogitMargin` 0.45。
精度は、特記がなければ最後の5エポックの平均テスト精度(%)。検証データは分けていない。

---

## 1. 畳み込みの組み方

パラメータを持たない層を2つ足し、`Dense` の「全行に同じ重みを使う」性質で畳み込みにした。

- `Im2Col{H, W, C, K, Stride}`: 1 × (H·W·C)(チャネルラスト: 列 = (y·W + x)·C + c)の入力から K×K の窓を切り出し、
  「位置 × 窓内の画素(K·K·C)」の行列にする。逆伝播は、画素を含む窓の希望ビットの多数決
- `Dense`(または `ProductDense`): 各行(位置)に同じ重みを掛ける = 畳み込み
- `Flatten`: 「位置 × フィルタ」を 1 行に並べ直す(チャネルラストの画像と同じ並び)

基本構成: `Im2Col(28×28×1, 7×7, stride 3) → 畳み込み 64 → Flatten(4096) → 全結合 512 → 1024`

crow 本体に入れる場合の注意:

- `Trainer.prepareRecords` は全層に `model.XRows` を渡しており、層ごとに入力の行数が変わる構成に対応していない。層ごとの入力の行数を渡す必要がある
- `Im2Col` と `Flatten` を1ビットずつ処理すると学習時間の半分以上を占めた。出力ビットごとの参照先を最初に表にし、ワード単位で読み書きすると
  1エポック 3.6〜4.3 秒 → 2.4〜2.6 秒になった(積の層の畳み込みの構成)
- 使い勝手のため、汎用の `Reshape` は bitsx に、画像をチャネルラストに並べる関数は crow 側に置くのがよい(未実装)

## 2. 畳み込みを学習させると固定より悪くなった(原因と解決)

当初は、どう工夫しても「畳み込みを学習させる」方が「初期値のまま固定する」より悪かった(MNIST 10エポック、1シード)。

| 試したこと | 学習させた精度 | 固定の精度 |
|---|---:|---:|
| 畳み込み → 全結合 → 出力(τ = 7) | 90.7 | 95.1 |
| 畳み込みの更新確率を 1/4・1/16 に下げる | 92.1 / 93.8 | 同上 |
| 合意の強さで絞る / 空白の窓を除く / 入力 1 だけ投票 | 89〜91 | 同上 |
| 局所的な目標(DRTP 型) | 81〜89 | 同上 |
| 下流の確信度で絞る | 91.7〜92.0 | 同上 |
| 三値の重み(不感帯) | 最良 94.8 | 同上 |
| 畳み込み → 出力(学習する層を2段に) | 93.7 | 94.2 |
| (対照)3層の全結合の第1層 | **92.6**(学習が効く) | 90.8 |

全結合なら第1層の学習は効くので、**重み共有と BEP の更新規則の組み合わせ**の問題と分かった。

### 2-1. PyTorch の勾配と突き合わせて原因を特定

BEP の状態(二値の重み・1バッチ)を書き出し、同じ重みの PyTorch モデル(符号関数の微分は tanh の微分で代用)で勾配を取って比べた。

- BEP が畳み込み層に渡す**目標(多数決)は、勾配の向きとよく一致していた**(全体 71%、勾配の大きい上位 10% の位置で 93%、上位 1% で 98%)
- しかし**畳み込みの重みのデルタは勾配とほぼ無関係**だった(符号一致 49.7%、cos +0.01)。全結合層は一致していた(cos +0.45〜0.77)
- 勾配による畳み込みの更新は、主に「**目標どおりだが境界に近い位置**」から来ていた。BEP は食い違った位置しか数えておらず、
  本来それを拾うマージンは既定値 isqrt(fanIn)/4 = isqrt(49)/4 = **1** で、z が奇数しか取らないため**実質 0** になっていた

| デルタの作り方(2エポック後の状態) | 勾配との cos |
|---|---:|
| 食い違い かつ |z| ≤ 7(マージン実質なし) | −0.01 |
| 食い違い |z| ≤ 7 + 正解 |z| < 7 | +0.59 |
| 全位置で |z| < 7(食い違い・正解とも) | +0.60 |
| 全位置、代用勾配の微分 × 下流の誤差の票 | +0.67 |

### 2-2. マージンを効かせると学習が固定を上回った(MNIST、1シード)

| 畳み込み層 | 10エポック | 20エポック |
|---|---:|---:|
| 固定 | 94.95 | 95.51 |
| **学習: τ = 7、マージン 7** | 95.32 | **96.17** |

マージン 15 ではフィルタが死んだ(18/64)。**BEP は、正解側の境界に近い部分を数えないと勾配の大事な成分を失う**
(UPDATE_SELECTION.md のノイズ = 確率的なマージン、と同じ根)。

## 4. しきい値の正規化(LayerNorm に近い)

τ・m を「√fanIn × 倍率」の固定整数で決めると、実際の |z| の大きさが層の種類・重み共有・学習の進みで変わるため、層ごとに手調整が要り、
値に敏感だった。そこで順伝播は変えず、**逆伝播での選択のしきい値だけ**を、そのサンプル・その層の |z| の平均 s で正規化した。

- 「|z| < c・s のニューロンを目標の向きへ押す」(食い違いと正解を区別しない)。層の間は二値なので、z を使う処理は層の中に置く
- 積の層では s = 各ニューロンの「枝の最小 |z|」の平均。「全枝の |z| の平均」「枝ごとの平均」も試したが、枝の大きさはずれておらず
  (20エポック後も |z| 平均 92.5 と 90.4、選択は 48:52)、結果もほぼ同じだった
- 追加の計算は |z| の和だけで、学習時間は変わらなかった

### 4-1. 比率の選び方(1シード、20エポック)

| 構成 | 今の規則 | 共通 c=1/4 | 共通 1/2 | 共通 1 |
|---|---:|---:|---:|---:|
| 全結合 MNIST / Fashion | 93.14 / 84.24 | 93.29 / 84.29 | 93.24 / 82.84 | 90.17 / 49.73 |
| 積の層 MNIST / Fashion | 94.91 / 84.34 | 93.40 / 82.91 | 89.97 / 75.90 | 11.35 / 22.20 |
| CNN MNIST / Fashion | 96.04 / 83.86 | 96.50 / 83.60 | 96.31 / 79.82 | 90.61 / 32.10 |

c を大きくすると崩れる崖は残る。積の層だけは、食い違いと正解で比率を分けた (c_誤り, c_正解) = (1/2, 1/8) が良かった
(MNIST 95.01、Fashion 84.52)。c_誤り は学習率のように働き、大きいと序盤が速いが頭打ちが早い。

### 4-2. 3シード・30エポックの確認

新方式: Dense は c = 1/4、ProductDense は (1/2, 1/8)。今の規則: 層ごとの τ・m(CNN の畳み込みは τ7・m7 に手調整)。

| 構成 | データ | 今の規則 | 新方式 |
|---|---|---:|---:|
| 全結合 | MNIST | 93.57 ± 0.05 | **93.71 ± 0.08** |
| | Fashion | **84.96 ± 0.07** | 84.83 ± 0.05 |
| 積の層 | MNIST | **95.36 ± 0.09** | 95.31 ± 0.09 |
| | Fashion | 84.75 ± 0.03 | **84.80 ± 0.10** |
| 通常の CNN | MNIST | 96.65 ± 0.12 | **96.90 ± 0.07** |
| | Fashion | 84.23 ± 0.28 | **84.40 ± 0.22** |
| 積の層の畳み込みの CNN | MNIST | **97.81 ± 0.07** | 97.10 ± 0.07 |
| | Fashion | **84.82 ± 0.13** | 83.73 ± 0.12 |

積の層の畳み込みの CNN だけ悪化。畳み込みの積の層の比率を変えた(後段は c = 1/4、3シード・30エポック):

| 畳み込みの積の層 (c_誤り, c_正解) | MNIST | Fashion |
|---|---:|---:|
| (1/2, 1/8) | 97.10 | 83.73 |
| (1/4, 1/4) | 96.80 ± 0.13 | **86.29 ± 0.12** |
| (1/2, 1/4) | 97.07 ± 0.03 | 85.00 ± 0.09 |
| **(1/2, 1/2)** | **97.89 ± 0.08** | 85.47 ± 0.18 |

- **重みを共有する層では正解側の押しが大事**(2 と同じ)。通常の CNN は Dense の c = 1/4 で正解側を押しているので下がらなかった
- Dense は全結合でも畳み込みでも c = 1/4 でよいが、**積の層は使い方で最適値が変わる**(全結合: (1/2, 1/8)、畳み込み: (1/2, 1/2))。
  全結合の積の層に (1/2, 1/2) を使うと崩れる(1シードで 89.97 / 75.90)
- crow に入れる場合の未決事項: 積の層の比率を重み共有の有無で自動で切り替えるか、利用者に設定させるか

## 5. 参考値

- PyTorch(小数、Adam、同じ二値化データと同じプロトタイプ、1シード・10エポック): MLP 97.45 / 86.14、
  CNN(同じ 7×7・stride 3・64 → 512 → 1024)98.37 / 87.62、同じ CNN で畳み込み固定 97.82 / 84.84、
  3×3 を2段の小さい CNN 98.71 / 87.68。小数では CNN の方がエポックあたりの学習も速く、畳み込みの学習は固定より良い
- BEP 論文は CNN の実験をしていない。画像(CIFAR-10・Imagenette)は AlexNet の特徴を入力にしており、
  畳み込みへの拡張(フィルタ単位のマスク、重み共有への対応、二値向けの正規化)は今後の課題としている
- 積の層を1本の Dense に正確に落とすことは不可能(2本の超平面の XNOR は線形分離できない)。Dense 3層なら正確に表せるが、大きく遅くなる

## 7. 多層の畳み込みと GAP(1シード、20エポック)

比率は Dense c = 1/4、積の層 (1/2, 1/2)。

| 構成 | MNIST | Fashion | 1エポック |
|---|---:|---:|---:|
| 1段(7×7・stride 3・64)→ Flatten → 512 → 1024 | **96.33** | **83.64** | 2.0 秒 |
| 2段(5×5・s2・32 → 3×3・s2・64)→ Flatten | 95.14 | 79.22 | 1.5〜2.0 秒 |
| 2段・幅広(64 → 128) | 95.88 | 80.67 | 2.5〜3.3 秒 |
| 2段・積の層 | 94.27 | 78.27 | 2.3〜3.1 秒 |
| 2段 → GAP(直前 64 フィルタ × 4 ビット) | 47.57 | 66.08 | 2.4 秒 |
| 2段 → GAP(直前 512 フィルタ × 4 ビット) | 60.99 | 66.52 | 5.0 秒 |

- **2段にすると悪化する**(Fashion で 3〜5pt)。1段目の畳み込みには、2段目の窓の多数決を経たさらに粗い目標しか届かない。
  通常の畳み込み1段でも、Fashion では全結合(84.8、3シード)をわずかに下回る。全結合を上回ったのは積の層の畳み込みだけ
- **GAP は使えない**。二値の GAP はフィルタごとの「1 の位置の数」を多数決や数ビットの温度計に丸めるが、その数はクラス間で数個しか変わらない
  (あるフィルタで数字 5・0・4・1・9 が 21・19・23・12・13)。直前のフィルタを 512 に増やしても 61% / 67% にとどまる。
  小数でも畳み込み1段の直後の GAP は弱い(PyTorch 5エポックで 79.5%)。GAP が機能するほど深い畳み込みを、今の BEP は学習できない
- GAP の実装: 順伝播はフィルタごとの 1 の数を Levels ビットの温度計(1 なら多数決)で出力。逆伝播は、目標の水準が今より高ければ全位置に 1、
  低ければ 0、同じなら今の出力を返す

## 8. 正規化は回帰の全結合で悪化した(3シード、20エポック、テストの MAE)

§4 の正規化(Dense c = 1/4、積の層 (1/2, 1/8))を回帰(温度計 101 レベル、点灯数で復号)で今の規則と比べた。
タスクは UPDATE_SELECTION.md §4 と同じ。

| タスク | 全結合 今の規則 | 全結合 正規化 | 積の層 今の規則 | 積の層 正規化 |
|---|---:|---:|---:|---:|
| 線形 | **0.0094** | 0.0186(+99%) | 0.0184 | 0.0183 |
| 積 | **0.0354** | 0.0380(+7%) | **0.0451** | 0.0516(+14%) |
| 波 | **0.0938** | 0.0961(+2.5%) | 0.0532 | **0.0329**(−38%) |
| MNIST の数字 | **0.883** | 0.941(+7%) | 0.925 | **0.759**(−18%) |

- **全結合は全タスクで悪化**した。分類では同等だったので回帰に特有。温度計の出力では大半のビットが境界から遠く、
  |z| の平均 s がそれに引っ張られて大きくなり、c·s のしきい値が直す必要のない正解のビットまで押している、と考えられる(未検証)
- この結果で、正規化は crow に入れないと判断した
