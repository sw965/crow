# 二値・三値の乗算ユニット（研究メモ）

BEP の層を乗算ユニットへ拡張する研究ラインのまとめ。
実装は [glulab/](glulab/)（二値）。

**この研究ラインは、ライブラリ構成の「1. シンプルな既存 BEP」には含めない扱い。**
精度を上げる方向の話であり、本体の方針（浮動小数を削って精度を保つ）とは別枠。

> **三値版（`ternary/gtlab`）の実装は 2026-09-24 に三値パッケージごと削除された。**
> 三値に関する記述（§4、§5-1 の三値行、§6-4）は**知見の記録として残してある**。
> 再び三値をやるなら、まず §4 を読むこと。二値の実装をそのまま移植すると失敗する。

---

## 1. 発端

依頼者と GPT の会話で「SwiGLU のようなゲートの掛け合わせを BEP でもできないか」という案が出た。
GPT の提案の骨子:

```text
u = sign(W_u x)
g = sign(W_g x)
a = u ⊙ g          ← ±1 同士の積なので ±1 に閉じる
```

枝の目標値は他方を固定すれば一意に決まる:

```text
u* = a* ⊙ g,   g* = a* ⊙ u
```

**この代数は正しい。** 検算済み。GPT は「0/1 ゲートにすると三値化して BEP の理論が壊れる」
という点も正しく指摘していた。

---

## 2. GPT の提案から変更した点（4件）

### 2-1. ★ 両枝を同時に補正してはいけない（GPT が見落としていた最重要点）

`u* = a*⊙g` と `g* = a*⊙u` は**各々「他方を固定したとき」に限って正しい条件付きの解**であり、
同時に適用できない。両枝を反転させると

```text
XNOR(¬u, ¬g) = XNOR(u, g)
```

で出力が元に戻る。したがって**1ニューロンにつき補正を流す枝は必ず1本**に絞る必要がある。

これは最適化ではなく**機構が動くための必要条件**。実測でも `route both` は 10.3%（偶然レベル）。

### 2-2. ★ 振り分けはニューロン単位でなければならない

GPT は「バッチごとに枝を交互に更新する（alternating BEP）」を提案していたが、
**これも失敗する**（`route alt` で 11.4%、偶然レベル）。

バッチ単位で切り替えると、同じニューロンがバッチごとに別の枝へ配線され、
2つの枝が受ける更新が互いを打ち消し合う。枝の符号一致率が 0.50 付近（＝無相関）から
動かないことと整合する。

動くのは `route cheap` だけ。**ニューロンごとにその場で** `argmin(|z_u|, |z_g|)` で選ぶ。
これは [layer.go](layer.go) の「直しやすい順」ソートの自然な一般化で、
出力の直しやすさが `|z_u|` と `|z_g|` の両方に依存することから導かれる。

### 2-3. 前層への合成が未指定だった

GPT は `a_prev* = sign(Wᵀ(...))` と書くだけで、2枝の票をどう合成するか書いていない。
採用したのは整数での加算:

```text
a_prev* = sign( W_uᵀ(gate ⊙ u*) + W_gᵀ(gate ⊙ g*) )
```

補正を受けなかった枝の目標値は現在の符号そのものなので、「変えなくてよい」という票として入る。

### 2-4. パラメータ対照は両側から挟む必要がある

GPT の「2倍幅との比較は必須」は方向としては正しいが、対照が片側だけでは不十分。
出力幅 K のゲート層は `2·K·fanIn` パラメータで K 出力、2倍幅の通常層は `2K·fanIn` で 2K 出力
（＝次の層のパラメータも倍になる）。

採用した設計は**隠れ層だけを広げる**もので、これにより重み数が厳密に一致する:

| arch | 構成 | 重み数 |
|---|---|---:|
| `plain` | 784 → 512 → 1024 | 925,696 |
| `wide` | 784 → **1024** → 1024 | **1,851,392** |
| `gated` | 784 → 512 → 1024（2枝） | **1,851,392** |

## 3. これは SwiGLU ではない（枠組みの訂正）

`sign(p)·sign(q) = sign(p·q)` なので、この層が計算しているのは

```text
a = XNOR( perceptron_u(x), perceptron_g(x) )
```

**2つの超平面の XNOR** である。単一パーセプトロンでは表せない線形分離不可能な関数（XOR そのもの）を
1ユニットで表せるようになる。

SwiGLU の強さは**連続値ゲート**（0.2倍・0.8倍と情報量を段階的に調整すること）から来るが、
`±1` の積にその成分は一切ない。`g = +1` なら素通し、`g = -1` なら符号反転、の2択でしかない。

したがって「BEP に SwiGLU を入れる」ではなく **「各ユニットの表現力を上げる」** と理解した方が正確で、
比較すべき対照も「ゲートの有無」ではなく**幅とパラメータ数**になる。

論文にするなら、売り文句は **「二値 XNOR ユニットに対する離散連鎖律を導出する」** の方が強い。

### 参考: 浮動小数モデルでの位置づけ

掛け算で束ねる場合、主流はほぼ例外なく2本（GLU / SwiGLU / GeGLU / Bilinear / SE）。
3次以上の積を常用する手法は無い（Product units、Π-Nets などの研究はある）。

一方、足し算・連結で束ねるなら Inception（4前後）、ResNeXt（32）、
Multi-head attention（8〜96）、MoE（8〜256）と、いくらでも増やす。

**掛け算だけが2で止まる理由**は、`∂/∂z₁(z₁z₂…z_k) = z₂…z_k` で1本への勾配が他の枝の積に支配されること、
および分散が `σ^(2k)` で効いて初期化・正規化が破綻すること。

例外は attention で、`softmax(QK^T)V` は x について実質3次の相互作用。
成立するのは softmax と `1/√d` が分散を構造的に抑えているため。
なお attention の掛け算は**トークン間**（`q_i · k_j`）であり、GLU 系の**トークン内**（`u_i × g_i`）とは別物。

## 4. 三値版で追加した設計（実装は削除済み。知見の記録）

> 三値パッケージは削除されたため、以下は再挑戦するときのための記録である。

### 4-1. 0 が吸収元 → 本物の ON/OFF ゲートになる

`{-1,0,+1}` の積は `{-1,0,+1}` に閉じる。しかも**どちらかの枝が 0 なら出力は 0**。

二値版は `±1` の積なので情報を落とせず「符号の変調」でしかなかったが、
**三値ではゲートとしての意味が自然に入る。** GPT が懸念していた「0/1 ゲートにすると三値化する」
という問題は、三値モデルでは最初から三値なので消える。

### 4-2. ★ 反転が常に解けるわけではない（三値固有・最重要）

`u ⊙ g = a` を `u` について解くとき、`g = ±1` なら `u = a⊙g` で一意だが、
**`g = 0` なら解が存在しない**（0 に何を掛けても 0）。

したがって補正を流せるのは「**他の枝の積 `p` が 0 でない**」枝だけで、そのとき

```text
want = a* · p        （p² = 1 なので want · p = a*）
```

補正可能な枝のうち補正距離が最小のものを選ぶ。2本以上が 0 で補正可能な枝が無い場合は、
1本を 0 から離して次の機会に備える（実測での発生率は1%前後）。

**この条件を無視すると、乗算ユニットはベースラインより悪化する:**

| route | MNIST |
|---|---:|
| `cheap`（可解性を考慮） | **95.54 ± 0.11** |
| `naive`（無視） | 90.18 ± 0.21 |
| `plain`（ベースライン） | 91.92 ± 0.33 |

差は **5.36pt**。代数から導いた制約が実測で5pt分の差として現れた。

## 5. 結果

### 5-1. 主結果（3シード、テスト精度 %）

| | plain | wide（重み数一致） | gated | gated − wide |
|---|---:|---:|---:|---:|
| 二値 MNIST（20ep） | 90.64 ± 0.08 | 90.87 ± 0.20 | **94.23 ± 0.16** | **+3.36** |
| 二値 Fashion（20ep） | 82.89 ± 0.25 | 82.81 ± 0.12 | **83.79 ± 0.28** | **+0.98** |
| 三値 MNIST（12ep） | 91.92 ± 0.33 | 92.50 ± 0.06 | **95.54 ± 0.11** | **+3.04** |
| 三値 Fashion（12ep） | 83.50 ± 0.44 | 83.95 ± 0.15 | **84.46 ± 0.17** | **+0.51** |

### 5-2. 3方向の対照すべてで勝つ

| 揃える基準 | 対照 | 結果 |
|---|---|---|
| パラメータ数 | `wide`（1,851,392 で厳密一致） | gated +3.36pt |
| 推論時間 | `wider2048`（23.5us 対 gated 22.3us） | gated +3.41pt |
| 幅を増やし続ける | 512→1024→2048 | **+0.23 → −0.05 で飽和** |

**幅の軸は使い切られている。** 重みを4倍（0.93M → 3.70M）にして +0.18pt、
1024→2048 ではむしろ悪化する。同じ2倍のコストを乗算構造に使うと +3.59pt。

### 5-3. 速度（二値、実測）

| arch | 重み数 | 推論(1サンプル) | 学習(1エポック) |
|---|---:|---:|---:|
| `plain` | 925,696 | 10.4us (1.00x) | 2.41s (1.00x) |
| `wide` | 1,851,392 | 13.5us (1.29x) | 4.32s (1.79x) |
| `wider2048` | 3,702,784 | 23.5us (2.26x) | 7.78s (3.23x) |
| `gated` | 1,851,392 | 22.3us (2.14x) | **2.71s (1.13x)** |

**学習と推論でコストの順序が逆転する。** 学習では重い処理が逆伝播のデルタ蓄積（fanIn 長の
スカラーループ）で、`cheap` は片枝しか補正しないためそこが増えない。推論にはその逃げ道が無く、
枝の数だけ行列積を打つ。

三値の学習時間は `plain` 13.6s に対し `gated` 13.9s でほぼ等速。**三値の推論速度は未測定。**

### 5-4. ノイズとの相互作用（二値）

MNIST、5エポック、seed 1:

| arch | noise 0 | 0.125 | 0.25 | 0.5 |
|---|---:|---:|---:|---:|
| `plain` | 0.8950 | 0.8993 | 0.8961 | 0.9010 |
| `wide` | 0.9001 | 0.9013 | 0.8958 | 0.9005 |
| `gated` | 0.9228 | 0.9148 | 0.9171 | **0.1332** |

`plain`/`wide` は平坦だが、`gated` は 0.25 と 0.5 の間に崖がある。理由は2つ:

1. ノイズはどちらの枝に乗っても XNOR の出力を反転させるので、**出力ノイズが実質的に倍**になる
2. `conf = min(|z_u|, |z_g|)` と `argmin` による振り分けがノイズで決まるようになり、
   **同じニューロンがサンプルごとに別の枝へ配線される**（`route alt` の失敗と同じ機構）

崩壊時の枝の符号一致率は 0.50 付近で、縮退（一致率が1へ張り付く failure mode）ではない。
**枝は無相関のまま、学習信号だけが失われている。**

**`gated` は `-noise 0.25` 以下で使うこと。最良は `noise 0`。**

## 6. 枝数 n への拡張（理論のみ。未検証）

コードは既に n 枝で動くように書いてある（`outputBit` / `productExcept` が全枝を畳み込む）。
`archSpec` が枝数を 2 に固定しているだけなので、フラグを1つ足せば回せる。

### 6-1. n≥3 は「一致したか」ではなく**パリティ**

`a = Π sign(z_b)` は **−1 の個数が偶数なら +1**。n=2 のときだけ「偶数個の−1」＝「2つとも同じ」
なので「一致したか」という説明が成り立つが、n=3 以降は崩れる。

| 3枝の答え | −1の個数 | 出力 |
|---|---:|---:|
| (+, +, +) | 0 | +1 |
| (+, −, −) | 2 | **+1** |
| (−, +, +) | 1 | −1 |

`(+, −, −)` は一致していないのに +1 になる。正しくは「n個の質問のうち"いいえ"が偶数個か」。

なお「全部一致したか」（AND 的な関数）は積では書けない。別の機構が要る。

### 6-2. 補正規則はそのまま使える

パリティは**どれか1本を反転させれば必ず出力が反転する**（1は奇数）。
`argmin(|z_b|)` で一番安い枝を1本選ぶ規則が n 枝でもそのまま正しい。
`route both` が失敗したのは「2本＝偶数本」反転させていたからで、**n枝でも奇数本なら正しい**
というのが一般形。

### 6-3. 劣化が予想される理由（3つ）

1. **学習信号が 1/n に薄まる。** 不一致1個につき直すのは1枝だけなので、
   各枝が受け取る補正は枝数に反比例する。重みは n 倍なのに1枝あたりの学習は n 倍遅い
2. **ノイズ耐性が指数的に落ちる。** 各枝が確率 p で符号を誤るとき、パリティが保たれる確率は
   `(1 + (1−2p)ⁿ)/2` で、n が増えると**指数的に 1/2（＝偶然）へ落ちる**。
   n=2 で既に noise 0.5 で崩壊しているので、崩壊する閾値はさらに下がるはず
3. **振り分けの手がかりが弱くなる。** パリティは「どの枝が悪いか」を出力から特定できない関数。
   `|z_b|` は代理指標にすぎず、候補が n 個に増えるほど当たりにくくなる

**予想: n=2 が最適か、n=3 まではプラス、n≥4 で劣化。**

### 6-4. 三値はもっと早く壊れるはず

0 が吸収元なので、どれか1枝が 0 なら出力が 0。実測で1枝あたりの非ゼロ率は約78%。

| 枝数 | 出力の非ゼロ率 | 出力が0の割合 |
|---:|---:|---:|
| 1 | 0.78 | 22% |
| 2 | 0.61 | 39% |
| 3 | 0.47 | 53% |
| 4 | 0.37 | **63%** |

n が増えると**出力がゼロに埋もれて情報を運ばなくなる。**
さらに「補正可能な枝」の条件（他の枝の積が 0 でない）も確率 `0.78^(n−1)` で減るので、
補正可能枝なし率が急増する（n=2 の実測で 0.7〜1.5%）。

対策は活性しきい値 `-act` を n に応じて下げることだが、別のトレードオフを生む。

## 7. 留保（重要）

- **MNIST で約3.5pt、Fashion で約0.9pt と効果量が4倍違う。** 符号は4条件すべてで一貫しているが、
  MNIST 寄りの現象である可能性は否定できない
- 検証したのは **MNIST と Fashion-MNIST の2層MLPのみ**。二値20エポック、三値12エポック
- **深さを増やした対照が未実施。** 乗算ユニットは「深さ2の構成を1層へ畳んだもの」とも解釈でき、
  利得が「深さの前借り」で説明できるかは切り分けられていない。`wide` は隠れ層のみを広げた対照
- **枝数は2のみ**
- 2枝経路の検証は単体テストのみ（`TestFlippingBothBranchesCancels`、`TestForwardMatchesNaiveReference`、
  `TestBackwardMovesOutputTowardTarget`、`TestTransposeStaysInSyncAfterUpdate`）。
  ただし `-arch plain`（1枝）は gatelab および本物の `ternary.Dense` と一致することを確認済みで、
  土台の妥当性は取れている
- [REPORT.md](REPORT.md) の本実装は MNIST 92.13 ± 0.48（50エポック）。
  設定が違うため今回の数値とは直接比較できない

## 8. 次にやるなら（優先順）

1. **深さを増やした対照。** 乗算ユニットの利得が深さの前借りで説明できるかの切り分け。
   §7 の留保のうち最も本質的なもの
2. **枝数 n のフラグ化と n ∈ {1,2,3,4} の掃引。** §6 の予想が当たるか外れるかは、
   それ自体が情報になる（特に「n=3 でも伸びる」なら予想2・3が外れていることになる）
3. **三値の推論速度の実測。** 二値では学習1.13倍・推論1.89倍と乖離した

5. ノイズを枝ごとに独立ではなく**共通**にする。振り分けの安定性だけを保ったまま
   ノイズの効果を残せる可能性がある
6. 振り分けの安定化。`argmin` をサンプルごとに取り直すのではなく、
   ニューロンごとに枝の割り当てを保持する
